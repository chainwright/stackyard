# How Stackyard is built with Kiro (running log)

Kept from day one for the Kiroween write-up.

## 30 Oct 2026: steering first
- Tool: Kiro CLI (`kiro-cli chat`), signed in with Google.
- Before any code, we asked Kiro to write the project steering from a one-paragraph brief: `product.md`, `tech.md`, `stack-format.md`, `audience.md` in `.kiro/steering/`.
- The stack format and its seven invariants (unique ids, valid goto targets, exactly one end card, one correct answer per quiz card, canvas bounds, non-empty title, at least one playable card) become the contract for the generator, the editor, the exporter and the property-based tests.
- First attempt drafted the files but did not write them (file tools were not trusted for the session); resumed the same session with write access and it saved what it had drafted.

## 30 Oct 2026: first spec (stack generator)
- Asked Kiro (CLI) for a spec of the first feature with EARS acceptance criteria. It wrote `.kiro/specs/stack-generator/{requirements,design,tasks}.md`: 7 requirements, a data-flow design (one LLM call → shared validator → one retry with the validator's errors → deterministic fallback stack if the model is down), and 9 tasks.
- The spec turned the steering's seven invariants into the validator contract and into one property-based test per invariant (fast-check).
- Cost so far: under 1 credit for steering and spec together.

## 30 Oct 2026: Phase 1 implemented by Kiro (types, validator, property tests)
- Kiro CLI implemented tasks 1–3 of the spec: `src/shared/types.ts`, `src/shared/validator.ts` (collects every failing invariant, no `any`), and `tests/validator.property.test.ts` (18 fast-check properties, one block per invariant).
- `npm test` 18/18, `tsc --noEmit` clean.
- We checked the tests can actually fail: removing any one of five invariant checks from the validator makes 1–2 property tests fail; restoring it brings 18/18 back.

## 30 Oct 2026: Phase 2 (prompt builder, fallback stack)
- Kiro implemented `server/promptBuilder.ts` (system prompt carries the schema, the seven invariants and the audience rules; card count clamped to 20; retry message leads with the validator's errors) and `server/fallback.ts` (3-card stack with ids seeded from the prompt).
- The service throttled the first run halfway; we resumed the same Kiro session and it finished the phase.
- Two fast-check properties (500 runs each): any non-empty prompt up to 500 characters gives a fallback stack that passes the validator, and the same prompt always gives the identical stack.
- 49/49 tests, `tsc` clean. Mutation check: turning the fallback's end card into a story card fails 5 tests.

## 30 Oct 2026: Phase 3–4 (LLM gateway, generator)
- Kiro implemented `server/llmGateway.ts` (OpenAI-compatible; base URL, model and key from env, read only in this file; key never in errors) and `server/stackGenerator.ts` (validate → one retry at lower temperature with the validator's errors → plain-language error; fallback stack when the model is unreachable).
- Throttled twice by the service mid-task; each time we resumed the same session and Kiro picked up where it stopped (it also fixed its own TypeScript precedence error and added Node types).
- Property tests: for any string and any JSON value the model might return, `generate()` never throws, returns a valid stack or a plain-language error, and never contains the API key.
- 89/89 tests, `tsc` clean. Mutation check: if the generator skips validation, 9 tests fail.

## 30 Oct 2026: Phase 5–6 (route, end-to-end) and a bug the tests missed
- Kiro implemented `POST /api/generate` on `node:http` (plain-language 400/422/500, response stripped to `{ ok, stack, isFallback }`) and an end-to-end test of the three paths. 113/113 tests, `tsc` clean. All 9 spec tasks are now ticked.
- A live run without an API key returned the fallback stack (good), but its ids were 38 characters, not UUID v4 as REQ-2 says. The validator only checks uniqueness, so no test caught it. Next: make the fallback ids real UUID v4 and add the format to the validator with a property test.
- Fixed with Kiro (two throttles, resumed both times): fallback ids are now real RFC 4122 v4 UUIDs, still deterministic; the validator gained invariant 8 (`invalid-id`); steering and spec updated to eight invariants; property tests for invalid ids and for every fallback id over 500 random prompts. The old "conforming stack" arbitraries had produced non-v4 ids, so Kiro switched them to a v4 generator rather than weakening the check.
- 118/118, `tsc` clean. Mutation check: removing the `invalid-id` check fails 3 tests. Live run: all 10 ids in a fallback stack match UUID v4.
- Lesson for the write-up: the spec and 113 green tests still let a real defect through; a 30-second live run caught it, and the fix went back into the spec as a new invariant.

## 30 Oct 2026: second spec (exporter + player) and a review round
- Kiro wrote `.kiro/specs/exporter/` (requirements, design, 18 tasks): one self-contained HTML file, player under 50 KB gzipped, stack JSON embedded for lossless re-import (fast-check round-trip), synthesised sounds, ES2018 target.
- We reviewed it like a pull request and sent five fixes back to Kiro: reuse the existing types/validator instead of re-specifying them; the right key variable name for the no-secrets test; a card-level auto-advance cycle could hang the player (now invariant 9 `goto-cycle` plus a runtime cap); image inlining must never read arbitrary paths from stack data (only data URIs or files inside one assets directory, path-traversal tests); a teacher's text containing a URL must still export with no raw `https://` and round-trip exactly.
- Kiro applied all five across requirements, design, tasks and the steering.

## 30 Oct 2026: invariant 9 and the player runtime
- Kiro added invariant 9 (`goto-cycle`: the card-level auto-advance graph must have no cycle) with property tests, `ExportValidationError`, and `src/player/runtime.ts` (state, dispatcher, `goto` stops the action list, injected sound callback) with 24 unit tests.
- 146/146, `tsc` clean. Mutation check: removing the cycle check fails 2 tests.

## 31 Oct 2026: design system as steering
- Three directions were mocked up at full fidelity (Stamp Pad, Bit Garden, Answer Tiles, plus a hybrid); the team picked the hybrid: a ring-bound pad with rubber-stamp feedback and shaped answer tiles (▲ ◆ ● ■) for kids and colour-blind readers. Reference: `docs/design/reference-stamp-pad-tiles.png`.
- Kiro wrote `.kiro/steering/design-system.md` from the exact tokens (colours, fonts, type scale, radii, motion, accessibility, banned AI-default patterns).
- Review round: we measured contrast with the WCAG formula instead of trusting estimates. The first stamp red (#E5402B) failed AA (3.88 on paper, 4.12 under white text), so Kiro switched it to #CE3926 (4.67 / 4.96), fixed a token typo and raised a 16px label to the 18px floor.

## 31 Oct 2026: the player, and why we review in a real browser
- Kiro built the player runtime pieces (scaler, renderer, audio, errors, entry point with a 20-step auto-advance cap) and the IIFE build: 6.4 KB gzipped against a 50 KB budget.
- All jsdom tests were green, yet the first look in real Chrome showed five problems the tests could not see: the card pinned top-left, small question text, the CORRECT stamp never visible (the goto fired instantly), an end card showing a bare "1", doubled ruled lines. We sent screenshots and measured numbers back to Kiro over four rounds (docs/design/review/).
- Each round was checked in a foreground Chrome tab (a background tab pauses CSS animations, which once made the stamp look faded). The stamp now lands on the tile's top edge and the answer stays readable; the end card says "Well done! Score N of M" with a stamp per correct answer; heading fallback is a grotesque, never a serif.
- 201 tests. The Kiro free monthly quota ran out at the end of this round; the rest waits for the hackathon credits.

## 4 Nov 2026: the exporter core (hackathon credits arrived)
- With the 4,000 hackathon credits active, Kiro picked the exporter spec up where the free quota stopped: TASK-11 `server/inline-assets.ts`, TASK-12 `server/html-template.ts`, TASK-13 `server/exporter.ts`, each with its own tests (23 new).
- Kiro hit a real macOS trap in its own tests: the temp folder `/var/...` is a symlink to `/private/var/...`, so the realpath check rejected valid asset paths. It canonicalised both sides of the comparison instead of loosening the check.
- 224/224 tests, `tsc` clean. Mutation check: switching off the realpath containment check makes the symlink-escape test fail.
- Then TASK-14 to TASK-18: no external URLs and no API key in an exported file, the URL-escaping round-trip, a stack → HTML → stack property test over 1,000 random stacks, the player size budget (about 6.4 kB of 50 kB gzipped) and a staleness check for the player bundle. 230/230, `tsc` clean.
- The no-URL test caught something real in already-finished code: the answer-tile SVGs carried `xmlns="http://www.w3.org/2000/svg"`, so every exported file contained an `http://` string. Kiro removed the redundant namespace (the SVG is injected into an HTML document) instead of loosening the test.
- Our review found the "committed" player bundle was in fact gitignored, so the staleness check compared a build with itself on a fresh clone. We now commit `dist/player/player.iife.js` on purpose.

## 4 Nov 2026: third spec, the Maker app
- Kiro wrote `.kiro/specs/maker/` from the steering and the two earlier specs: 16 requirements in EARS form, 23 tasks, three property tests (any edit sequence stays valid, undo restores the exact stack, export after any edit round-trips). It ended with four open questions instead of guessing.
- Our answers went back as a review round: the export is served byte-exact as text/html with a safe filename; Play mode and the exported file share one `mountPlayer`, so the preview is literally what the class gets; a burst of keyboard nudges is one undo step; Preact for the UI. We added one task Kiro hadn't planned: draw every screen state as a static mockup before any UI code (states before code). 25 tasks now.

## 4 Nov 2026: Maker logic (no UI yet)
- Kiro implemented TASK-01 to TASK-10 and the three property tests of the Maker spec: `POST /api/export` (byte-exact HTML, safe filename, plain-language JSON errors), undo/redo history with nudge coalescing, browser-only persistence with validate-on-load, the store's single `apply` chokepoint, and nine pure edit operations. 300/300 tests, `tsc` clean.
- Each property test was broken on purpose and went red: switching off validate-before-commit (P1, any edit sequence stays valid), switching off nudge coalescing (P2, undo restores the exact stack), and making the exporter alter the title (P3, export after any edit round-trips).
- Our review of the new route found that both POST routes read the whole body with no size limit, so one large request could exhaust memory on the public demo. Kiro added a shared `readBody(req, res, maxBytes)` (16 KB for generate, 8 MB for export, 413 with a plain message, stream destroyed) and export caps (200 cards, 10,000 characters per text field), with tests that the downstream work never runs over the limit. Switching the byte check off turned three tests red. 311/311, `tsc` clean. The rule now lives in the tech steering.

## 4 Nov 2026: Maker screens designed before code (four review rounds)
- TASK-10M: Kiro drew every Maker screen state as static HTML in the Stamp Pad system. An outside design review scored the set 5.0, then 6.8, then 7.8, and the last fixes take it to about 8. What changed across the rounds: the card scaled to the screen with nothing under 18 px, the real fonts embedded offline, rings, stack edges, an ink stamp and the desk restored, direct editing on the card, the "Try It" flip (one card turns over and plays), and a start screen that deals cards with real questions while it builds.
- Licences: the fonts ship with their OFL texts. Atkinson Hyperlegible declares a Reserved Font Name, so the subset is renamed inside the font's name table to "Stackyard Reading" (`scripts/rename-reading-font.py`), and a test fails the build if any embedded font still carries the reserved name.
- The design-system steering was brought up to date with every rule the mockups depend on, so the UI pass builds from the same spec.

## 5 Nov 2026: the Maker UI, built against the mockups
- Kiro built TASK-11 to TASK-20 and TASK-17a in Preact (the only new dependency, pinned), screen by screen against the approved mockups, with screenshots of the built screens in `docs/design/maker/built/` at 1366×768 and 1920×1080. Play mode and the exported file now run the same `mountPlayer`.
- Our review of the first pass found three things: `tsc` was red in tests (one error came from our own previous commit, which we had not type-checked), the four toolbar tools were "coming soon" stubs, and the canvas merged the "Card 3 of 10" line into the question and lost the rings. Kiro fixed all three: strict `tsc` clean without loosening the config, four real add-element operations in the spec with EARS criteria and inside the edit-sequence property tests (local pictures as data URIs with required alt text and a 2 MB cap), and the canvas matching the mockup.
- 393/393 tests, `tsc` clean, player bundle 6.4 kB gzipped.
- Player chrome: the exported file now draws "Card N of M", the standing rings and a live score as derived chrome from one place (`renderCard`), used by both the editor canvas and the player, so nothing is stored in the stack and the round-trip test is unchanged. Exported a real stack and checked it in Chrome at both sizes against the play mockups. Player 7.1 kB gzipped.
- Streaming: `POST /api/generate` can answer in NDJSON (start, card, done or error), each card validated before it's written. Our review: the first version waits for the whole stack and then sends the cards, so the "dealing" is cosmetic; real progressive delivery from the model is the next step.
- 413/413, `tsc` clean.
- Real progressive delivery: the streaming path now asks the model for JSON Lines, parses the token stream incrementally (`LineBuffer` reassembles split lines) and sends each card the moment its line completes and validates; the whole stack is validated at the end, and any failure resets the dealt cards and falls back with a plain message. The offline fallback deals at a small fixed pace, labelled in the code as fallback-only. A test asserts the first card reaches the client before the stream ends. 435/435, `tsc` clean.
- Deadlines on both model calls (45 s; streaming 90 s total and 20 s idle) via AbortController, and a client that closes the page mid-stream now aborts the upstream call, so the server stops paying for tokens nobody reads. Fake-timer tests for each case. Mutation check: emitting a line before its newline turned three split-chunk tests red. 443/443, `tsc` clean.

## 5 Nov 2026: a judge ran the built app (5.0) and we fixed it to match the mockups (7.8 set)
- An outside judge drove the running app, not just the screenshots, and scored it 5.0 against the 7.8 mockup set (`docs/design/review/MAKER_MOCKUPS_JUDGE.md`, "Built app verdict"). The shell matched Round 3, but everything the *class* sees was the Round 1 player. We fixed the six things the verdict put first, in order, each with `npm test` + `tsc` green and a re-shoot.
- **The game ended on the first click.** Every quiz answer in the demo stack, the generator and the fallback pointed at the last card, so one tap jumped to "Score 0 of 6". A new pure `linkQuizAnswersForward` (shared) points every quiz answer at the NEXT card (only the last quiz targets the end), wired into the demo deck, the LLM path and the fallback. A property test proves no answer targets the end card unless it is the last question, and a play-through test walks every card in order to a real end score.
- **The class never saw the design.** The player renderer asked for `Atkinson Hyperlegible` (never loaded — the app ships it renamed as `Stackyard Reading`), and the exported file embedded no fonts at all. Fixed the family names and made the exporter inline all three woff2 as base64 `@font-face` with the OFL notice, no external URL, so the file is still fully offline. A test asserts three font data URIs, the notice, and that no reserved name ("Atkinson"/"Hyperlegible") appears; the 50 KB budget is the player bundle only (the fonts live in the export).
- **Nothing flipped, and Try It started at card 1 full-screen.** Try It is now an in-editor mode: the same card the teacher is editing flips over in place (the design-system rotateX, respecting reduced motion) and plays, with the editor chrome kept and a "Back to Editing" pill; the player flips on every card change. The old `PlayOverlay` is gone; `mountPlayer` gained `startCardId`, `flip` and a scaler seam.
- **The offline fallback was placeholder cards.** With no model key it returned a 3-card "Correct Answer"/"Wrong Answer" stub. It now returns real ready-made decks — the Vikings quiz, a times-tables game, everyday Irish words — matched to the Start-screen examples; any other sentence gets the closest deck with an honest "ready-made example" note.
- **Ported the Round 3 player look**: the ink stamp straddling the tile's top edge (transparent, multiply), a full-strength boxed ✗, the 64px end-card stamp collection, and the warm desk with grain. Plus real pointer drag through `moveElement` (one coalesced undo step), Add Button on a quiz no longer restyling the four tiles, and Add Text landing in free space.
- **The polish list**: no score while editing, card counts that agree, the flash Front/Back switch un-clipped, long labels that fit, the export overlay over the editor, start-empty pre-filled, and the generating counter matching the card.
- 460/460 tests, `tsc` clean. Re-shot every built screen and the exported player and compared by eye against the mockups.

## 5 Nov 2026: second built-app verdict (5.0 → 6.5) fixed to about 8
- The judge ran the app again and scored it 6.5 (`docs/design/review/MAKER_MOCKUPS_JUDGE.md`, "Built app verdict, round 2"). Quiz play and the export were at mockup level; two things held it back — flash cards and the story branch — plus a handful of polish items. We fixed them in the order the verdict gave, each with `npm test` + `tsc` green and a re-shoot.
- **Flash cards didn't flip.** The player gave every flash text the 44 px question class and showed term and answer at once, with no flip, so the whole Irish-words example demonstrated the bug. The renderer now draws the FRONT only (the term, centred); a tap or Enter/Space flips to the BACK (the explanation in body type, 26 px) with the rotateX card flip, a tap flips back, and "Next Card" sits on the back only, clear of the text — matching `play-flash-back.html`. A played-flash test taps front → back → Next Card, and plays the whole Irish deck end to end to its real score.
- **The story branch was fake.** Both Vikings choices ("Raid the monastery" / "Build a longphort") went to card 6. Each choice now leads to its own consequence card (the raid, and the longphort), and the two rejoin visibly after the choice; the demo deck was fixed the same way. The generator prompt (both the single-object and the streaming path) gained a "Story cards" rule telling the model to give each choice its own card and rejoin after. A new non-blocking `warnStack` flags any story card whose choices all share one target (a warning, not an error — a teacher may mean it), surfaced as a gentle note in the inspector; tests cover the warning and both built decks.
- **The offline deal told a fib.** The fallback dealt ten cards in ~1.5 s with an "About 20 seconds" line. The fallback pace is now ~400 ms a card (~4 s for ten, so each card lands), and the building line is honest per path: "About 20 seconds" only for the live model, "Each card appears as it's ready." offline.
- **The card list showed the flash answer.** Flash rows used the longest text (the back). They now show the front term ("Dia duit", "Longphort").
- **The toolbar stayed live during Try It.** Add Text while trying silently edited the card. The whole toolbar is now dimmed and every control disabled (visually and for keyboard) while trying; "Back to Editing" flips the card out with the card-exit animation before returning.
- **Polish:** adding an element to a full card is now rejected with "This card is full…" rather than dropping it on top of another; the editor "→ Card N" branch labels are centred and distinct; the end-card inspector shows a read-only score preview instead of a stray heading; the Try It inspector has a paper box and spacing and, when started mid-deck, says the score only counts the cards played; and a wrong answer briefly reveals the right tile with a faint ink outline before advancing.
- 478/478 tests, `tsc` clean, player bundle 9.08 KB gzipped (of 50 KB). Re-shot every built screen plus new flash-front/back, story and exported-player flash/story shots, and compared by eye against the mockups.

## 5 Nov 2026: third built-app verdict (6.5 → 7.8) and the last fixes to the bar
- The judge drove the app a third time and scored it 7.8, just under the 8 bar (`docs/design/review/MAKER_MOCKUPS_JUDGE.md`, "Built app verdict, round 3"). Every flow a judge is likely to try now worked end to end offline; three things were left. We fixed them, each with `npm test` + `tsc` green and a re-shoot. (A network error cut the first attempt off mid-edit, leaving the changes in the tree with 11 new tests failing; the only thing actually broken was that the two new test files weren't registered in `vitest.config.ts`'s jsdom glob list, so they ran under Node with no `document`. Wired them in and finished.)
- **The "This card is full" notice stuck and could trap Try It.** The notice is `EditorScreen` component state and was only cleared on the next toolbar action, so it survived a card change and the Try It toggle (the screen is reused for both views, so it never remounts) and in Try It it pushed the canvas down under the "Back to Editing" pill, which then did nothing. Now the card list clears it on selecting another card, the Try It toggle clears it on enter and leave and the banner never renders in the play view, and `.try-pill` gets a positive `z-index` so it always sits above any banner. A test drives the real app: raise the notice, change card → gone; enter Try It → gone and the pill returns to the editor.
- **The flash back collided on the Irish deck.** The renderer already lays the back out from fixed CSS (it never reads the authored x/y), but the full-width flip hint ran under the bottom-right "Next Card", so "Tap the card to flip back" read as "Tap the card". The hint is now capped to the left column and left-aligned, clear of the Next Card — one fixed back layout (term top-left, body left-aligned, hint bottom-left, Next Card bottom-right) on any deck. A test renders a deliberately colliding deck and the real Irish deck and asserts the fixed classes and that the hint and Next-Card rects don't intersect.
- **The small items.** The pre-filled sentence said "A 10-card quiz" while the Vikings deck is 12 cards; it now describes the real lesson (quiz questions and a story choice). The end-card inspector preview was a hard-coded "Score 3 of 8"; it now shows the deck's real quiz-card total ("Score __ of 6"), the same denominator the player uses. And the exported end card gained a navy "Play Again" tab (never stamp red) that resets the score and auto-nav guard via a new `resetRuntime` and goes back to card 1 with the flip, so a class can go again without reloading the file.
- 489/489 tests, `tsc` clean, player bundle 9.46 KB gzipped (of 50 KB). Re-shot the Irish answer side (new `exported-player-irish-back`), Try It, the end card (new `exported-player-end`, showing "Score 0 of 6" and the Play Again tab) and the exported player; the Irish back is left-aligned with the hint and Next Card clear of each other.

## 5 Nov 2026: one public web service (TASK-21)
- Kiro made Stackyard deployable as a single Render web service, spec first (TASK-21 a–f in `.kiro/specs/maker/tasks.md`). The same Node process now serves the built Maker and the API, plus `/api/health` for a keep-warm pinger.
- The live demo holds a paid model key, so generation is fenced twice. A per-visitor limit (6 decks per 10 minutes, memory-bounded) answers 429 with `Retry-After` and a human message. A daily cap on real model calls (300) switches everyone to the ready-made decks once it is reached, so the worst-case cost of a day is fixed even if the per-visitor limit is dodged.
- Static files are served with traversal rejected (encoded `..`, backslashes, NUL), immutable caching for hashed assets, and security headers including a CSP the built Maker actually runs under.
- 531/531 tests (42 new), `tsc` clean; Kiro also ran the production build and probed it with curl.
- Our review note: on Render the client address comes from the first `X-Forwarded-For` entry, and a visitor can set that entry themselves. We will check the real header chain on the first deploy and switch to the proxy-set address. Until then the daily cap is what bounds cost.
